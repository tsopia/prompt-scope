# PromptScope × Claude Design 交互手册

配套文件：`design-brief.md`（下面说"贴 A 段""贴 E2"都是指 brief 里对应编号的段落）。

## 你和它的分工

- **claude.ai/design** = 你 prompt，它用 React 实时渲染出 UI，你在浏览器里当场看到。
- **你 = 设计总监**：给方向、看渲染、给具体反馈、拍板定稿。
- **它 = 执行**：出设计、按你的反馈改。
- **三条铁律**：① 一次只推进一屏；② 每次基于你看到的渲染给**具体、可执行**的反馈；③ 每屏定稿后，让下一屏**复用同一套视觉语言**。

---

## 全流程九步（每步都有可复制的话术）

### 第 0 步 · 先让它"懂"，再让它"做"
新建一个设计项目。第一条消息贴 brief 的 **A + C + D + F** 段，末尾加这句：

> 以上是我要重新设计的产品背景和视觉方向。**先不要出任何设计**。请先用你自己的话复述一遍：这个产品是给谁用的、核心动线是什么、视觉方向最关键的几点（尤其那 5 个语义状态色，和"数据/ID/token 用等宽字体"这条）。我确认你理解对了，再开始。

看它复述——有偏差立刻纠正。**这一步是防它一上来就跑偏的保险。**

### 第 1 步 · 先定"视觉语言"，不要先出页面
先锁地基，后面每屏都站在它上面，天然统一。话术：

> 在做具体页面之前，先给我这个产品的**视觉基础**，用一屏展示出来：
> - 配色：深色为主（observatory 天文台感），青色作主强调色；5 个语义状态色——🔵实时 / 🟣回放 / 🟢成功 / 🟡偏离 / 🔴失败，给出它们在深色背景上的具体色值。
> - 字体：正文/UI 用一个现代无衬线，数据/ID/token 用等宽字体，给出搭配。
> - 间距节奏、圆角，以及一个卡片、一个按钮、一套状态徽章的样式。
> 我要先锁定这套语言，之后每一屏都基于它，不要再变。

实时看、反馈调（"色调太蓝了""字体换一个""太挤""圆角太大"），直到满意。

### 第 2 步 · 主入口：链路列表（最重要的一屏）
> [粘贴 E2]
> 用刚才定好的视觉语言做这一屏。重点：能高效扫描大量行、数据列用等宽且右对齐、来源和状态用语义色徽章。

这屏定下**表格、徽章、数据展示**的基准，后面详情/对比/回放全复用它。多迭代几轮到满意再往下。

### 第 3–7 步 · 逐屏推进（每屏都念同一句"咒语"）
顺序建议：**详情(E3) → 对比(E4) → Prompt 库(E5) → 回放(E6) → 设置(E7) → 登录(E1)**。登录放最后当收尾亮点。每屏：

> [粘贴对应的 E 段]
> **沿用前面已经定好的视觉语言（配色、字体、间距、徽章、表格/卡片样式）**，做这一屏。

各屏额外提醒它：
- **详情(E3)**：调用链树 + 节点详情左右两栏；数据密集，分区要清晰；树节点用状态色圆点。
- **对比(E4)**：左右对齐视图 + 偏离标记（🟡）+ 评分结果卡。
- **登录(E1)**：全屏、无侧边栏；可用等宽字体渲染一条 agent 调用链当氛围，点题。

### 第 8 步 · 连贯性/流程检查
逐屏做完后，检查动线顺不顺：

> 把 链路列表 → 点开一条 → 详情 → 从某一步发起回放 → 回放结果 → 去对比 串成一个可点击的流程原型，我要检查这条动线的下钻和返回顺不顺。

哪里跳转别扭就让它调。

### 第 9 步 · 落地
满意后两条路：
- **拿回来找我（Claude Code）落码**：把设计的关键决定（配色/字体/布局/各屏）告诉我，我帮你落回现有的 shadcn + Tailwind 代码。
- **design-sync**：如果你想让 claude.ai/design 直接用你的真实组件产出可交付代码，再回来做同步（需要我能看到渲染的环境，或接受降级）。

## 交互要领（贯穿全程，最影响成败）

1. **一次一屏**。别让它一次出全站——会糊、会不一致。
2. **反馈要具体可执行**：说"成本列右对齐 + 等宽""这个卡片阴影太重，去掉""留白再多些""状态徽章太抢眼，弱化"——**不要只说"不好看"**，它改不动模糊反馈。
3. **反复强调两条灵魂**：① 5 个语义状态色语义全站统一；② 数据/ID/token 用等宽。它一偏就拉回。
4. **每屏定稿要说清**："这屏定了，下一屏沿用它的语言。"——它才会保持一致。
5. **跑偏立刻纠**：它自造组件或改了基调 →"回到我们定好的深色 observatory + 青色基调，别自己发明。"
6. **善用实时渲染**：盯着它渲染出来的样子即时调，这是这套流程最大的优势。

## 速查表：什么时候给它什么

| 时机 | 你给它什么 | 期望它产出 |
|---|---|---|
| 开场 | brief 的 A + C + D + F 段 + "先复述你的理解，别急着设计" | 它对产品/方向的复述（你据此纠偏） |
| 定语言 | "先出视觉基础 + 卡片/按钮/徽章三个基础组件" | 一屏 style tile（配色/字体/组件样例） |
| 每一屏 | 对应的 E 段 + "沿用已定的视觉语言" | 该屏设计 |
| 连贯 | "把这几屏串成可点击的流程原型" | 可走通的流程 |
| 落地 | 回 Claude Code 落码，或做 design-sync | 可交付代码 |

---

## 一句话总纲
先让它懂产品 → 先锁一套视觉语言 → 从链路列表这屏定基准 → 逐屏复用同一套语言 → 串流程验动线 → 拿回来落码。全程你盯着实时渲染、给具体反馈、每屏拍板。
