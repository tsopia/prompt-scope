# PromptScope UI 重设计 Brief（详细版）

> 用途：贴到 claude.ai/design 重构 UI。**用法**：先贴「A 产品 / C 设计方向 / F 硬约束」建立整体认知，再进入「E 逐屏规格」——做哪一屏就复制哪一节作为该屏指令，每屏看渲染再迭代，满意后让 agent「沿用上一屏的间距/字体/状态色语言」再做下一屏。

---

## A. 产品是什么

PromptScope 是一个**自托管的 Agent 调优与回放平台**，给 AI agent 开发者用。他们的 agent 通过 SDK 上报每次运行的完整调用链（LLM 调用含 messages/工具定义，工具调用含 input/output），平台帮他们：可视化调用链、并排对比两次运行、多模型交叉评分、录制回放（换模型/prompt 重跑、工具用录制结果 mock、支持单步回放）、管理 prompt 版本。类比 Langfuse / LangSmith，核心特色是「录制回放 + 对比调优」。团队内部工具，多租户（工作区 + 成员）。

## B. 用户与核心动线

用户 = AI agent 开发者，数据密度高、需快速扫描和下钻。主动线：
> 跑出一批 trace → 在**列表**筛选定位 → 打开**详情**看哪一步出问题 → 换模型/改 prompt **回放** → **对比** + 多模型**评分** → 把好的 prompt 存成**新版本**

重设计要让 列表↔详情↔回放↔对比 的下钻/回流少点击、状态可追。

## C. 设计方向（重点）

- **现代、简约、大气、高级**：克制、充分且一致的留白、清晰层级。参考 Linear / Vercel / Grafana，拒绝模板感。
- **深色优先**，同时支持浅色（双主题都成立）。当前基调 "observatory / 天文台"：深蓝黑背景 + 青色强调。可在此基础上做得更精致。
- **语义状态色（产品灵魂，全站用法统一）**：🟢 成功/通过 · 🟡 偏离/警告 · 🟣 回放 replay · 🔵 实时 live · 🔴 失败。
- **等宽字体承载数据**：trace ID / 模型名 / token / 成本 / 延迟 一律等宽 + tabular-nums 对齐。
- 正文/UI 用现代无衬线（Geist / Inter 一类），中文走系统字体（PingFang SC）。
- **中文界面**（导航：链路 / 对比 / 提示词 / 设置）。
- 技术栈：**React + Tailwind**（当前 shadcn/ui + next-themes），产出希望能落回此栈。

## D. 全局外壳

左侧固定侧边栏（可折叠）：品牌标识 → 工作区/项目切换（下拉）→ 主导航（链路/对比/提示词/设置）→ 底部（当前账户 + 亮/暗/跟随系统主题切换）。当前项纯青色高亮（左边条 + 淡底）。**登录页例外：全屏、不挂侧边栏。** 每个内容页顶部有统一的页头（面包屑 + 页面标题 + 右侧动作槽），内容区统一的边距与区块间距。

## E. 逐屏规格

### E1 · 登录 `/login`
- **布局**：全屏、无侧边栏。推荐分屏——左侧登录表单，右侧产品氛围区（也可居中卡片，但要有个性，别做成通用登录框）。
- **左/表单**：品牌标识（logo mark + PromptScope）→ 小标题「登录到你的工作区」→ 邮箱、密码输入 → 主按钮「登录」→ 底部「没有账号？注册」切换。
- **右/氛围（signature）**：用等宽字体静态渲染一条 agent 调用链（`llm → tool → llm → 回放 → 评分`，节点点亮语义状态色），一眼点题"这是看 agent 链路的工具"。可配极淡网格底纹。
- **状态**：登录中按钮 loading；错误红色提示；注册模式多一个「显示名」字段；仅当后端允许注册时才显示注册切换。

### E2 · 链路列表 `/traces`（主入口）
- **页头**：标题「链路」；下方 filter bar = 搜索框（按名称）+ 来源筛选（全部 / 实时 / 回放）。
- **主体**：数据表格，列依次为——名称 · 来源徽章（🔵实时 / 🟣回放）· 状态徽章 · 模型（等宽，多个用逗号）· 步数 · 输入/输出 token（等宽、右对齐）· 成本（等宽）· 延迟 · 创建时间。
- **交互**：行 hover 高亮、整行可点进详情；行首 checkbox 多选。勾选后底部浮出对比托盘「已选 N 条 · 开始对比」，恰好选 2 条时「开始对比」可用，跳 `/compare`。
- **状态**：加载用骨架行；空态给引导（如何用 SDK 上报第一条 trace，带一步步指引）。

### E3 · 链路详情 `/traces/[id]`
- **页头**：面包屑「链路 / {名称}」+ 来源/状态徽章 + 摘要指标行（总成本 · 总延迟 · 总 token · 步数，全等宽）。
- **主体两栏**：左 = 调用链树，右 = 选中节点详情。
- **调用链树**：层级缩进的树，每个节点 = 状态色圆点 + 类型标签（llm/tool/span）+ 名称或模型 + 该步指标（延迟/token）。可展开/收起子节点；点击选中并高亮。
- **节点详情面板**（随选中变化，数据密集，清晰分区）：
  - llm 节点：messages 序列（role + 内容气泡）、模型与参数、token/成本、工具定义。
  - tool 节点：input / output（JSON，等宽，可折叠）。
  - 回放产生的 tool 节点标「mocked」徽章 + tooltip（说明是录制结果）。
- **动作**：整条 live trace 顶部有「回放 ▶」；选中的是 live trace 的 llm 节点时，节点区出现「单步回放此步 ▶」。

### E4 · 对比 `/compare`
- **页头**：面包屑「链路 / 对比」+ 两条 trace 名（A / B）。
- **差异摘要**：A vs B 的成本/延迟/token 并排（等宽数字 + 差值；差值用中性或语义色，别误导）。
- **对齐视图**：把两条调用链逐步对齐成行，每行标记「两侧都有 / 只在 A / 只在 B」；两侧都有的 tool 若参数不同，标「参数偏离」（🟡）。左右两列分别对应 A、B。
- **评分面板**：选裁判模型（下拉，来自已配置的可用模型）+ 上下文模式 →「运行评分」→ 结果卡：裁决（单条 pass/fail；成对 A/B 哪个可替代）+ 分数 + 理由。支持多个裁判模型、结果可缓存复用。

### E5 · Prompt 库 `/prompts`
- **布局**：左右两栏。
- **左栏**：当前项目的 prompt 列表 + 顶部「新建 prompt」（名称唯一）。
- **右栏**：选中 prompt 的版本历史（卡片列表，新→旧）。每张版本卡：版本号 · 内容预览 · 创建时间 · 动作「基于此版本新建」(fork，不改旧版) / 「用此版本回放…」(选一条 live trace) / 可展开「使用此版本的 traces」。
- **diff**：勾选两张版本卡 → 版本列表上方出现 `v旧 → v新` 的行级文本 diff（增/删行用绿/红底染色）。

### E6 · 回放 `/replay/[id]`
- **页头**：面包屑 + 源 trace 名 +「回放」；若是单步回放，标明是哪一步。
- **配置区**：覆盖模型（下拉）· 温度 · system prompt（文本域，或切换成「用某个 prompt 版本」）→ 主按钮「运行回放 ▶」（同步执行，按钮 loading）。
- **结果区**：状态徽章（成功/失败）· 错误信息（如有，红）· 偏离列表（param_mismatch / unrecorded_call / max_steps 等，🟡 逐条）· 跳转（「去对比」a=源&b=结果 /「看结果 trace」）。成功后可自动跳到对比页。
- **历史**：该源 trace 的历次回放（时间线，每条带状态徽章，新→旧）。

### E7 · 设置 `/settings`
- **页头**：标题「设置」+ Tab 栏：项目与密钥 / 模型 Provider / 定价 / 成员。
- **项目与密钥**：项目信息 + API 密钥表格（前缀 · 创建时间 · 状态）；「新建密钥」后用对话框**一次性**显示完整 key（带复制按钮，此后不可再取）；可撤销。
- **模型 Provider**：provider 表格（名称 · base_url · 类型 openai/anthropic · api_key 是否已设）+ 增/删/改（api_key 只写不回显）。
- **定价**：pricing 表格（模型 · 每 1K 输入价 · 每 1K 输出价 · 关联 provider）+ 增/删/改。
- **成员**：成员表格（邮箱 · 显示名 · 角色 owner/member）；owner 可按邮箱添加已注册用户、移除成员（不能移除自己或最后一个 owner）。

---

## F. 硬约束
- 深色 + 浅色双主题都成立（用语义 token，禁止硬编码颜色）。
- 语义状态色语义全站统一，不挪用。
- 表格/调用链树承载高密度信息且不拥挤，宽内容横向可滚动、不撑破页面。
- 全中文文案。
- 桌面为主；移动端不横向溢出。
